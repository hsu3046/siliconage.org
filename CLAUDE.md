# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

The Silicon Age — interactive knowledge graph of 100 years of digital history. Single-page React app deployed as a static site on Vercel. ~200 entities (Companies, Persons, Technologies) connected by typed links, visualized as a D3 force graph + chronological timeline + filterable card grid + relationship explorer.

## Commands

```bash
npm run dev               # Vite dev server on http://localhost:3000
npm run build             # vite build + scripts/prerender.ts (static node pages, sitemap, /data JSON, llms.txt)
npm run preview           # Preview the production build

# Pre-generated AI Deep Dives (GEMINI_API_KEY + OPENROUTER_API_KEY for the Jev check)
npm run deepdive -- --only openai --locale ko   # try one
npm run deepdive                                # all missing/stale → public/deepdive/<locale>/<id>.json

# i18n pipeline — extract source strings from constants.ts, then translate via AI
npm run i18n:sync-all     # extract + translate nodes, links, events (all three locales)
npm run i18n:sync         # nodes only
npm run i18n:sync-links   # links only
npm run i18n:sync-events  # events only

# Review-queue triage with TypeSafe Jev (needs OPENROUTER_API_KEY + migration 0007)
npm run triage -- --dry-run --limit 20   # preview verdicts
npm run triage                           # score unscored pending candidates
```

No test suite, no lint script. `vite build` does NOT type-check — run `npx tsc --noEmit` before committing.

Debug dashboard: `http://localhost:3000/debug` (dev-only, lazy-loaded so it's excluded from the production bundle).

## Architecture

### Data lives in one file
`constants.ts` (~155 KB) is the source of truth for the entire graph: every node, link, era, and event is a hand-curated entry. There is no database and no API. Adding or editing an entity = editing `constants.ts` and re-running the i18n sync.

`types.ts` defines the schema. Key shapes:
- `NodeData`: `{ id, label, category (COMPANY/PERSON/TECHNOLOGY), year, impactRole, techCategoryL1/L2, ... }`
- `LinkData`: `{ source, target, type (POWERS/CREATES/CONTRIBUTES/ENGAGES), arrow, icon, strength, story?, startYear?, endYear? }`
- Roles are strongly typed enums per category (`PersonRole`, `TechRole`, `CompanyCategory`).

Authoring rules for nodes and links: see `docs/NodeLinkRules.md` and `docs/LabelingRules.md`. Follow these when editing `constants.ts` — IDs, role assignments, and link types follow specific conventions.

### Computed ranking
`utils/ranking.ts → calculateSiliconRank()` is run **once at module load** in `App.tsx` against `INITIAL_DATA`. It mutates each node with `_radius` / `_zoneRadius` derived from link weights × category multipliers × tech-role bonuses. Don't run this per-render — graph sizing must stay stable across navigations.

### Four views over the same dataset
`App.tsx` holds top-level state (`viewMode`, `selectedNode`, `focusNodeId`, locale, URL sync) and renders one of:
- `MapView` — D3 force-directed graph (the main view)
- `HistoryView` — chronological timeline
- `CardView` — filterable card grid
- `LinksView` — pairwise relationship explorer

URL state is round-tripped via React Router 7 (`hooks/useUrlState.ts`) — deep links to `/node/:id` and view-mode routes must keep working. Initial-load sync uses `isInitialLoadRef` to avoid clobbering router state before the URL is read.

### AI deep dives (BYOK)
`services/geminiService.ts` powers on-demand entity analysis via Google Gemini. Two layers:
1. **Pre-generated Deep Dives** (`public/deepdive/<locale>/<id>.json`) — written by `scripts/generateDeepDive.ts` (Gemini from the node's curated description + connections, then a TypeSafe Jev consistency check that drops contradicted/vague facts). Fetched lazily per node, embedded in prerendered pages, incremental via `sourceHash`.
2. **Live API** — only used when the user has pasted their own key into About → API Key Settings. Key is stored in `localStorage` (`silicon_age_api_key`), never sent to any server we control.

When adding new nodes, run `npm run deepdive` (only new/changed nodes are regenerated) or those nodes fall through to "live key required".

### i18n architecture
Three locales: `en`, `ko`, `ja`. Translations split into four JSON files per locale under `locales/<lang>/`:
- `ui.json` — UI strings (hand-edited)
- `nodes.json`, `links.json`, `events.json` — generated by `scripts/translate-*.ts` from `constants.ts`

Runtime: `utils/i18n.ts` + `hooks/useLocale.ts`. Locale changes are async (`loadLocale`) — components must handle the pre-loaded state. `translateNode` / `translateLink` / `translateEvent` look up by ID and fall back to the original (English-source) string.

**When you edit a node label, description, link story, or event in `constants.ts`, run `npm run i18n:sync-all`** to regenerate translations. The extract scripts diff against the existing locale files so only changed entries hit the translation API.

### Path alias
`@/*` resolves to repo root (see `vite.config.ts` and `tsconfig.json`). Use `@/components/...` over deep relative paths.

## Conventions

- **Edit `constants.ts`, not generated locale files.** Locale JSON is rebuilt by the i18n pipeline.
- **No backend.** Everything ships as static assets. Don't introduce server routes or API handlers — this repo is not Next.js.
- **Strict TS, no `any`.** When extending `NodeData` / `LinkData`, update `types.ts` first.
- **License: GPL v3.** Copyright KnowAI. Don't remove license headers.

### Static prerender (SEO / GEO)
`scripts/prerender.ts` runs after `vite build`. It writes `dist/<cat>/<id>.html` plus `/ko/…` and `/ja/…` variants (served extensionless via `cleanUrls` in `vercel.json`; static files win over the SPA rewrite). Each page has localized title/description, canonical + hreflang, JSON-LD and a readable fallback article inside `#root` that React replaces on boot. `/ko` and `/ja` path prefixes are **entry-only**: `initLocale()` reads them and `App.tsx` strips them before routing; in-app navigation still writes unprefixed URLs. It also emits `dist/sitemap.xml` (hreflang), `dist/llms.txt`, `dist/data/graph.json` and `dist/data/lineage/<id>.json` (CORS-open, consumed by aib vote). Do not hand-edit `public/sitemap.xml` — the build output replaces it.

### aib vote bridge
`config/aibLinks.ts` maps AI-era node ids to aib vote lab slugs / news keywords for the DetailPanel "Now on aib vote" block. Lab slugs must exist as `pricing_services.slug` on aib vote — a wrong slug is a 404 on the partner site. Strategy and roadmap: `docs/ROADMAP_2026-11.md` (internal — `docs/` is gitignored).

### Jev triage
`services/jevClient.ts` (Node-only) + `scripts/triageCandidates.ts` score the `ai_discovered` queue: `jev_relevance` (P(belongs)) and role/category suggestions with confidence (`nodes.jev_*`, migration 0007). `/admin` sorts by Jev and can bulk-select by threshold — approval stays human. Shuffle choice options every call (position bias), pin the model version, calibrate thresholds on hand labels.
